# VNC & Printer Manager

Docker-контейнер для управления VNC серверами и принтерами через веб-интерфейс.

## Возможности

- **Управление VNC серверами**: добавление, редактирование, удаление VNC серверов
- **Управление принтерами**: мониторинг и управление сетевыми принтерами
- **Группировка**: организация серверов и принтеров по группам
- **Веб-интерфейс**: современный интерфейс для управления
- **noVNC**: подключение к VNC прямо в браузере
- **Статус мониторинг**: проверка доступности серверов и принтеров
- **Импорт/Экспорт**: резервное копирование и восстановление данных

## Быстрый старт с Docker

### Требования
- Docker
- Docker Compose (опционально)

### Запуск через Docker Compose (рекомендуется)

1. Клонируйте репозиторий:
```bash
git clone https://github.com/yourusername/vnc_print_manager.git
cd vnc_print_manager
```

2. Запустите контейнер:
```bash
docker-compose up -d
```

3. Откройте браузер и перейдите по адресу:
- Веб-интерфейс: http://localhost:5000
- noVNC прокси: порт 6080

### Запуск через Docker

1. Соберите образ:
```bash
docker build -t vnc-print-manager .
```

2. Запустите контейнер:
```bash
docker run -d \
  --name vnc-print-manager \
  -p 5000:5000 \
  -p 6080:6080 \
  -v $(pwd)/instance:/app/instance \
  vnc-print-manager
```

## Конфигурация

### Переменные окружения

- `FLASK_APP`: файл приложения (по умолчанию: app.py)
- `FLASK_ENV`: окружение (production/development)
- `NOVNC_PROXY_PORT`: порт для noVNC прокси (по умолчанию: 6080)
- `NOVNC_TOKEN_TTL_SECONDS`: время жизни токена noVNC (по умолчанию: 600)

### Тома (Volumes)

- `/app/instance`: логи и временные файлы
- `/app/vnc_manager.db`: база данных SQLite

## Использование

### Основные функции

1. **Добавление серверов VNC**:
   - Перейдите в раздел "Серверы"
   - Нажмите "Добавить сервер"
   - Введите IP, порт и название

2. **Добавление принтеров**:
   - Перейдите в раздел "Принтеры"
   - Нажмите "Добавить принтер"
   - Введите IP и название

3. **Подключение к VNC**:
   - Нажмите "Подключиться" рядом с сервером
   - Или используйте noVNC для подключения в браузере

4. **Управление группами**:
   - Создавайте группы для организации устройств
   - Назначайте цветовые метки группам

### noVNC (веб-VNC)

Для подключения к VNC через браузер:
1. Нажмите кнопку "noVNC" рядом с сервером
2. Откроется новая вкладка с VNC сессией
3. Введите пароль VNC если требуется

## API

### Основные эндпоинты

- `GET /api/groups` - получить группы
- `POST /api/groups` - создать/обновить группу
- `DELETE /api/groups/<id>` - удалить группу

- `GET /api/servers` - получить серверы
- `POST /api/servers` - добавить сервер
- `PUT /api/servers/<id>` - обновить сервер
- `DELETE /api/servers/<id>` - удалить сервер

- `GET /api/printers` - получить принтеры
- `POST /api/printers` - добавить принтер
- `PUT /api/printers/<id>` - обновить принтер
- `DELETE /api/printers/<id>` - удалить принтер

- `POST /api/connect/<id>` - подключиться к VNC
- `POST /api/novnc/<id>/token` - получить токен noVNC

- `GET /api/export` - экспорт данных
- `POST /api/import` - импорт данных

## Траблшутинг

### Проблемы с подключением VNC

1. **Проверьте доступность сервера**:
```bash
ping <IP_адрес>
telnet <IP_адрес> <порт>
```

2. **Проверьте VNC клиент**:
- Убедитесь что VNC сервер запущен на удаленной машине
- Проверьте настройки файрвола

3. **Для noVNC**:
- Убедитесь что порт 6080 доступен
- Проверьте логи контейнера: `docker logs vnc-print-manager`

### Проблемы с базой данных

База данных SQLite хранится в файле `vnc_manager.db`. При использовании Docker убедитесь что том смонтирован корректно.

### Логи

Просмотр логов контейнера:
```bash
docker logs vnc-print-manager
docker logs -f vnc-print-manager  #实时日志
```

## Безопасность

1. **Измените порты по умолчанию** в продакшене
2. **Используйте HTTPS** через reverse proxy (nginx/apache)
3. **Ограничьте доступ** по IP адресам
4. **Регулярно делайте бэкапы** базы данных
